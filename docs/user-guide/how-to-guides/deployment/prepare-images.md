# Prepare Container Images

Both Docker and Kubernetes deployments need Scenescape's container images available in the target environment before you deploy. Choose one of the two options below, then continue to [Deploy on Docker](./deploy-docker.md), [Deploy on Kubernetes](./deploy-kubernetes.md), or [Deploy the Demo](./deploy-demo.md).

## Prerequisites

- Verify you meet the [System Requirements](../../get-started/system-requirements.md).
- A checkout of the Scenescape repository (see [Get Scenescape](../../get-started/installation.md#step-1-get-scenescape)).

## Option A: Build from Source

Run these commands from the repository root as a standard, non-root user:

```bash
make
```

This is the same as `make build-core`: it generates secrets and certificates, builds the core microservice images (Manager, Scene Controller, Analytics, Auto Camera Calibration), and installs the default OpenVINO Model Zoo models. The build takes around 15 minutes, depending on the target machine.

By default, the build runs in parallel with one job per processor. Adjust with `JOBS`, for example to build sequentially:

```bash
make JOBS=1
```

To also build the Tracker, Mapping, and Cluster Analytics images (required for the Tracker deployment mode, or for the Mapping and Cluster Analytics services):

```bash
make build-all
```

`make build-all` builds the Mapping image with the default MapAnything model only. To build both Mapping variants (MapAnything and VGGT), run:

```bash
make -C mapping build-all
```

See [Build Mapping Service from Source](../../microservices/mapping-service/build-from-source.md) for the resulting image tags.

### (Optional) List Image Dependencies

```bash
make list-dependencies
```

This generates dependency lists, with separate files for system packages and Python packages per microservice image.

## Option B: Use Prebuilt Images

Prebuilt images are published on Docker Hub:

- [Scenescape Manager](https://hub.docker.com/r/intel/scenescape-manager)
- [Scenescape Controller](https://hub.docker.com/r/intel/scenescape-controller)
- [Scenescape Analytics](https://hub.docker.com/r/intel/scenescape-analytics)
- [Scenescape Autocalibration](https://hub.docker.com/r/intel/scenescape-autocalibration)
- [Scenescape Tracker](https://hub.docker.com/r/intel/scenescape-tracker)
- [Scenescape Cluster Analytics](https://hub.docker.com/r/intel/scenescape-cluster-analytics)
- [Scenescape Mapping](https://hub.docker.com/r/intel/scenescape-mapping): `<version>` and `<version>-mapanything` contain MapAnything; `<version>-vggt` contains VGGT

### Docker

Skip building images by generating secrets and models only:

```bash
make init-secrets install-models
```

`docker compose up` pulls any image that is not already present locally, so the subsequent deploy step in [Deploy on Docker](./deploy-docker.md) or [Deploy the Demo](./deploy-demo.md) fetches the prebuilt images automatically.

### Kubernetes

The chart pulls images from `repository` (default `docker.io`) using the published image names and the version in `kubernetes/scenescape-chart/Chart.yaml`, generated by `make -C kubernetes chart.yaml`. If your cluster can already reach `docker.io`, no further action is required; continue to [Deploy on Kubernetes](./deploy-kubernetes.md).

To build from source and make the images available to Kubernetes instead, push them to a container registry reachable from your cluster and override `repository` when installing the chart (see [Deploy on Kubernetes](./deploy-kubernetes.md)). For a local Kind cluster managed by this repository's tooling, see [Scenescape on Kubernetes](/kubernetes/README.md) instead, which builds and loads images into the cluster automatically.
