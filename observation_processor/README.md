# Observation Processor Service

The Observation Processor service (`scenescape.observation_processor.v1.ObservationProcessorService`) exposes a
single gRPC endpoint, `ProcessDetections`, that conditions 2D detections into
mesh-aware world-space measurements for the tracker. It combines two libraries
available under [`spatial_performance_primitives/`](../spatial_performance_primitives/):

- **frustum_gaussian** — projects 2D bounding boxes into ray-elongated 3D
  Gaussians (position, covariance, depth bounds, confidence).
- **observation_conditioning** — the amodal reasoner, which conditions each
  Gaussian on the static scene mesh (floor contact, occlusion, walls).

Scene (mesh), camera, and asset definitions are fetched from the Manager REST
API via `scene_common.rest_client.RESTClient`, using a dedicated service
secret.

## Layout

- `proto/` — published gRPC contract (`observation_processor.proto`); generated typed stubs
  are committed under `src/observation_processor/grpc_api/`
- `src/observation_processor/` — service sources
- `../spatial_performance_primitives/frustum_gaussian/` — frustum-gaussian library; the C++/TBB
  kernel is built as a wheel (scikit-build-core) in the image builder stage
- `../spatial_performance_primitives/observation_conditioning/` — amodal reasoner library

All Python dependencies, the frustum-gaussian wheel, and `scene_common` are
installed into a `/opt/venv` virtualenv in the builder stage; the runtime
image only copies the finished venv.

## Build

```bash
make -C observation_processor
```

To regenerate the committed gRPC stubs after changing the contract, use an
environment with `grpcio-tools==1.71.2` (pinned in `tests/requirements.txt`) and run:

```bash
make -C observation_processor proto
```

The root build also exposes the optional `observation_processor` image target.
To run it alongside the Scene Controller profile, build the image and deploy
with both profiles enabled:

```bash
make observation_processor
make deploy DEPLOY_PROFILES="controller observation-processor"
```

The gRPC service is private to the Compose network at
`observation-processor.scenescape.intel.com:50052`; this profile makes it
available for future pipeline integration but does not yet route Controller
requests to it.

To send a sample request from inside the running service container, replace the
scene and camera IDs with IDs from your deployment:

```bash
docker compose exec observation-processor \
  python3 -m observation_processor.client \
  --scene-id "$SCENE_ID" --camera-id "$CAMERA_ID" \
  --category person --box 54 25 20 46 --mode full --include-diagnostics
```

The client defaults to `localhost:50052` when run inside the Observation
Processor container. A client available in another container on the Compose
network can pass `--target observation-processor.scenescape.intel.com:50052`.

## Run

The service listens on `OBSERVATION_PROCESSOR_SERVICE_PORT` (default `50052`). Liveness
and readiness are exposed through the standard `grpc.health.v1.Health` service;
readiness requires at least one successfully warmed configuration snapshot.

Static data (scenes, cameras, assets) is fetched with the dedicated
`observation_processor.auth` secret (generated by `make init-secrets`, provisioned as a
non-superuser read-only account by the Manager). The cache is warmed on
startup and refreshed when the Manager publishes `update` on
`scenescape/cmd/database` (same auth file is used for the MQTT subscription);
there is no time-based expiry. The readiness worker loads all GLB scene meshes
and builds amodal reasoners for calibrated cameras before reporting `SERVING`,
so the first detection does not pay mesh-loading or depth-baking costs.
Uncalibrated cameras are skipped with a warning; scenes without GLB maps need
no mesh. Refreshes compare mesh content and pose, reusing unchanged meshes and
camera reasoners. Replacing a GLB at the same URL still rebuilds affected geometry;
camera calibration changes rebuild only the corresponding reasoners.
The previous snapshot is replaced only after the new one is completely loaded;
requests continue using the previous snapshot while its replacement warms.
Failed refreshes or Manager outages retain that snapshot and readiness `SERVING`,
with failures logged and refreshes retried. Until initial warmup succeeds,
readiness remains `NOT_SERVING` and requests return `UNAVAILABLE`.
Database events received during loading schedule another refresh rather than
publishing obsolete data. Broker reconnects also schedule a refresh to recover
missed events. Database events wake the readiness worker immediately; periodic
probes and failed-refresh retries use `OBSERVATION_PROCESSOR_READY_INTERVAL_SECONDS`.
Scene meshes are read from the shared media volume when mounted, with an
authenticated HTTPS download as fallback.

## ProcessDetections

The typed unary RPC is defined in [`proto/observation_processor.proto`](proto/observation_processor.proto).
It accepts a scene ID, camera ID, protobuf acquisition timestamp, conditioning
mode and an ordered list of raw-pixel bounding boxes with categories.

- `AUTO`: use full conditioning for GLB scenes, frustum-only otherwise.
- `FULL`: native C++ frustum projection followed by amodal mesh conditioning.
- `FRUSTUM_ONLY`: skip amodal conditioning; per-object `project_to_map` can still
  intersect the scene mesh.

Headless OpenCV (the same version used by the other services) undistorts box
corners using the stored camera calibration. Supported distortion vectors have
4, 5, 8, 12 or 14 coefficients; Manager's named coefficient dictionaries are
also accepted. Rectified corner bounds define the pinhole box. Clipping flags
come from the original image bounds with the library's 3-pixel margin.
The bottom-centre pixel is undistorted separately for mesh-foot projection.

Size priors and default flags come from the category's object-library asset.
Unknown categories use the contract's pedestrian prior. Optional per-detection
booleans override asset flags, including explicit `false`. Invalid asset
dimensions are errors, not a pedestrian fallback.

Each detection returns an OK measurement or `DEPTH_UNOBSERVABLE` (for example a
zero-size box). Frustum and amodal diagnostics are optional and are returned only
when `include_diagnostics` is true in the request. Unobservable detections do not
enter the amodal reasoner. Measurements contain 7 mean values
`[x, y, z, length, width, height, yaw]` and 49 row-major covariance values.
The position block preserves lateral frustum noise and replaces along-ray
variance with the selected source's variance, floored at `1e-4` m².
Size/yaw diagonal noise is `0.2`; yaw is zero and unobserved, and Z is measured.
Mesh-foot hits lift the surface point by half the prior height and cap
along-ray variance at `0.05²` m²; misses retain the frustum/amodal result.

Each frame pins one warmed snapshot, so concurrent refreshes cannot mix
configuration versions. Pending or failed refreshes continue serving the last
successfully warmed configuration, which may be stale until a refresh succeeds.
RPCs return `UNAVAILABLE` only when no warmed snapshot exists; requests never
perform cold mesh loads as part of a refresh.
Empty detection lists are valid; scene, camera and mode are still checked.
Errors apply to the whole frame:

| gRPC status           | Cause                                                                                                                |
| --------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `INVALID_ARGUMENT`    | Missing fields, invalid timestamp/mode, nonfinite or negative box values, or values outside the native float32 range |
| `NOT_FOUND`           | Unknown scene or camera, including a camera outside the scene                                                        |
| `FAILED_PRECONDITION` | Invalid camera calibration or FULL mode without a mesh                                                               |
| `UNAVAILABLE`         | No successfully warmed configuration snapshot available                                                              |
| `INTERNAL`            | Projection, prior resolution or conditioning failure                                                                 |

Clients decide whether to retain their legacy projection after a frame error;
this service never silently substitutes it.

# Service configuration

Service can be configured through the following environment variables if required:

| Variable                                       | Default                                   | Purpose                              |
| ---------------------------------------------- | ----------------------------------------- | ------------------------------------ |
| `OBSERVATION_PROCESSOR_SERVICE_PORT`           | `50052`                                   | gRPC listen port                     |
| `OBSERVATION_PROCESSOR_REST_URL`               | `https://web.scenescape.intel.com/api/v1` | Manager REST API                     |
| `OBSERVATION_PROCESSOR_AUTH`                   | `/run/secrets/observation_processor.auth` | REST + MQTT credentials              |
| `OBSERVATION_PROCESSOR_ROOTCERT`               | `/run/secrets/certs/scenescape-ca.pem`    | TLS root certificate                 |
| `OBSERVATION_PROCESSOR_MEDIA_ROOT`             | `/workspace/media`                        | shared media volume mount            |
| `OBSERVATION_PROCESSOR_BROKER`                 | `broker.scenescape.intel.com`             | MQTT broker (database-change events) |
| `OBSERVATION_PROCESSOR_READY_INTERVAL_SECONDS` | `10`                                      | readiness probe interval             |
