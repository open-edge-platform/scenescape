# Update-Dependencies Script

This script updates dependency lists for the current version by comparing previous release dependencies with current build dependencies and generating an updated dependency list with license information.

## Overview

The script implements intelligent dependency matching and license tracking across software releases, handling version updates, moved dependencies, and license resolution from SBOM data.

## Usage

**Important**: Run this script from the repository root directory so it can properly access Dockerfile paths specified in the image list.

```bash
# Run from repository root directory
python3 tools/dependencies/update_dependencies.py --from <previous-release.csv> --deps <current-make-generated.csv> --sbom <dockerfile-sboms-folder> --image-list <images.csv> [--output <output-file.csv>] [--show-new]
```

### Arguments

- `--from`: Previous release CSV file with dependencies and license information
- `--deps`: Current dependencies CSV file generated by `generate_dependencies.py`
- `--sbom`: SBOM folder containing CSV files with license information for each image
- `--image-list`: CSV file with image list containing Dockerfile paths and published status
- `--output`: Output CSV file name (default: `updated-dependencies.csv`)
- `--show-new`: Add "New" column to output CSV to indicate new dependencies (optional)

### Example

```bash
# Run from repository root directory
python3 tools/dependencies/update_dependencies.py \
    --from tools/dependencies/release-data/SceneScape-1.4.0-deps.csv \
    --deps build/all_dependencies.csv \
    --sbom build/sboms \
    --image-list tools/dependencies/release-data/SceneScape-1.5.0-images.csv \
    --output build/SceneScape-1.5.0-deps.csv \
    --show-new
```

## Input File Formats

### Previous Release CSV (`--from`)
```csv
Image,Component,Origin,License,Distributed by you?,Comments
scenescape-controller,libdbus==1.0.0,Ubuntu,Apache-2.0,Y,imported
scenescape-manager,requests==2.32.4,pypi,MIT,Y,HTTP library
```

### Current Dependencies CSV (`--deps`)
Generated using `generate_dependencies_csv.py` (run from repository root):
```csv
Image,Component,Origin
scenescape-controller,libdbus==1.1.0,Ubuntu
scenescape-manager,requests==2.32.5,pypi
```

### SBOM Folder (`--sbom`)
```
sboms/
├── scenescape-camcalibration-sbom.csv
├── scenescape-common-base-sbom.csv
└── ...
```

Each SBOM CSV file format:
```csv
Image,Component,Origin,License
scenescape-camcalibration,libtest:1.0.0-1,Ubuntu,GPL-2.0
scenescape-camcalibration,newpkg==2.0.0,pypi,Apache-2.0
```

**Note**: The script handles component name normalization for Ubuntu packages by removing architecture specifications (e.g., `:amd64`) when matching with SBOM data.

### Image List CSV (`--image-list`)

Required columns:
- `Image`: Image name (must match dependencies files)
- `Dockerfile Path`: Path to Dockerfile relative to workspace root
- `Report Dependencies`: Y/N - whether to process this image
- `Published`: Y/N - whether image is published to DockerHub

```csv
Image,Dockerfile Path,Dockerfile Name,Report Dependencies,Published,Comment
scenescape-manager,manager/Dockerfile,Dockerfile-manager,Y,Y,
scenescape-controller,controller/Dockerfile,Dockerfile-controller,Y,Y,
scenescape-mapping,mapping/Dockerfile,Dockerfile-mapping,Y,N,
```

For images with `Report Dependencies=Y`, the script adds base image dependencies:
- Component: `<base-image-with-tag>` (extracted from Dockerfile with variable resolution)
- Origin: `Ubuntu`, License: `collection of licenses`, Distributed: `N`, Comments: `base image`
- **Variable Resolution**: Supports Dockerfile ARG variables (e.g., `${RUNTIME_OS_IMAGE}` → `ubuntu:24.04`)

## Processing Rules

The script implements 6 main dependency matching rules:

### 1. Exact Match (COPIED_DEPENDENCY)
When `(image, component, origin)` exists in both previous and current with identical versions:
- **Action**: Copy license, distributor, usage from previous release
- **Log**: `COPIED_DEPENDENCY,<full row>`

### 2. Version Update (UPDATED_DEPENDENCY)
When same `(image, component_name, origin)` exists but with different version:
- **Action**: Reuse license, distributor, usage; update version
- **Log**: `UPDATED_DEPENDENCY,<full row>`

### 3. Cross-Image Reuse (REUSED_DEPENDENCY)
When `(component_name, origin)` exists but in different image:
- **Action**: Reuse license, distributor, usage with `?` prefix for manual review
- **Log**: `REUSED_DEPENDENCY from <source_image>,<full row>`

### 4. Missing Images (IMAGE_NOT_FOUND)
When image exists in previous but not in current:
- **Action**: Do not add to output
- **Log**: `IMAGE_NOT_FOUND <image>,<full row>`

### 5. New Dependencies (ADDED_DEPENDENCY)
When `(component_name, origin)` doesn't exist in previous:
- **Action**: Add with `?` placeholders for license, distributor, usage
- **Log**: `ADDED_DEPENDENCY,<full row>`

### 6. Removed Dependencies (REMOVED_DEPENDENCY)
When `(component_name, origin)` exists in previous but not in current:
- **Action**: Do not add to output
- **Log**: `REMOVED_DEPENDENCY,<full row>`

### License Resolution (LICENCE_IDENTIFIED)
Final step for dependencies with `?` license:
- **Action**: If `(image, component)` exists in SBOM and license ≠ "NO ASSERTION", update license
- **Log**: `LICENCE_IDENTIFIED,<full row>`

## Output Files

### 1. Updated Dependencies CSV
Sorted by: image name, origin, component name
Contains all current dependencies with resolved license information.

When `--show-new` option is used, an additional "New" column is added as the last column with:
- `Y` for dependencies that are new to the image (ADDED_DEPENDENCY and REUSED_DEPENDENCY cases)
- `N` for dependencies that existed in the same image in the previous release (COPIED_DEPENDENCY and UPDATED_DEPENDENCY cases)

### 2. Log File (`<output>-log.txt`)
Complete trace of all processing decisions:
```
COPIED_DEPENDENCY,scenescape-controller,pkg==1.0.0,pypi,MIT,Y,comment
UPDATED_DEPENDENCY,scenescape-controller,pkg==2.0.0,pypi,MIT,Y,comment
ADDED_DEPENDENCY,scenescape-controller,newpkg==1.0.0,pypi,?,?,?
REUSED_DEPENDENCY from image1,image2,pkg==1.0.0,pypi,?MIT,?Y,?comment
LICENCE_IDENTIFIED,scenescape-controller,newpkg==1.0.0,pypi,BSD-3-Clause,?,?
```

### 3. Action List (stdout)
User actions required:
- Review dependencies reused across images (where `?` prefix added)
- Fill in placeholders `?` for license, distributor, usage
- Double check missing images
- Review resolved license information
- Identify missed dependencies (JavaScript, build prerequisites, etc.)

## Component Name Extraction

The script intelligently extracts component names for comparison:

- **pip packages**: `ConfigArgParse==1.7.1` → `ConfigArgParse`
- **APT packages**: `libx11:amd64:1.7.5-1` → `libx11:amd64`
- **Simple names**: `package-name` → `package-name`

## Features

- **UTF-8 BOM handling**: Supports CSV files with Byte Order Marks
- **Robust error handling**: Continues processing on individual line failures
- **Comprehensive logging**: Full audit trail of all decisions
- **Flexible output**: Customizable output file names
- **Statistical reporting**: Summary counts of all operation types
- **Action guidance**: Clear user instructions for manual review tasks
- **Image-based distribution status**: Automatically sets "Distributed by you?" field based on `Published` status in image list
- **Base image extraction**: Analyzes Dockerfiles to extract base images, supports multi-stage builds (runtime stage detection)
- **SBOM license resolution**: Component name normalization for Ubuntu packages (removes architecture specifications)
