Comments from CoPilot:

1. PipelineEngine stores tracker outputs as an iterator (process_inputs returns an iterator). TrackEvalEvaluator consumes that iterator into a list, so subsequent calls to evaluate() (or any reuse) will see an exhausted iterator. Consider materializing outputs once (e.g., store a list) or otherwise ensuring the stored value is re-iterable
https://github.com/open-edge-platform/scenescape/pull/987#discussion_r2805832164

2. In MotChallenge3DPoint._load_raw_file, tracker_confidences and gt_extras['zero_marked'] are taken from column 6, but per the documented CSV layout conf is column 5 and column 6 is class. This will overwrite confidences with class IDs and can change CLEAR/HOTA scoring once real confidences/classes are used. Update the parsing to pull confidence/zero_marked from the correct column(s).
https://github.com/open-edge-platform/scenescape/pull/987#discussion_r2805832131

3. MotChallenge3DPoint._load_raw_file documents an 8-column format (frame,id,x,y,z,conf,class,visibility) but parses classes from column 7 (visibility). This will mislabel classes as visibility and can corrupt metric results when class/visibility differ. Adjust the column indices (and/or the written CSV format) so class is read from the intended column.
https://github.com/open-edge-platform/scenescape/pull/987#discussion_r2805832105
